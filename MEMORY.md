## Big pivot (2026-09-19): rebuild from scratch, not patch

Original plan (see task.md history) was to fix the existing Create React App site in place. Superseded: the user found a reactbits.dev / 21st.dev component to use for almost every section, so patching the old markup first just to tear it out again would be wasted work. **New approach: rebuild the site from scratch in a new Next.js project, porting real content (not markup/styling) from the old site as each section is built.**

## Decisions made

- **2026-09-19 — Hosting: Vercel** (superseded nothing, still current). Chosen over Cloudflare Pages for DX/preview deployments.
- **2026-09-19 — Framework: ~~Vite~~ → Next.js (App Router).** Originally planned Vite; revised same day once the "rebuild from scratch" pivot happened. Chosen because it lines up with the SEO phase (file-convention sitemap/robots/OG-image generation, Metadata API) and is Vercel's own framework (zero-config deploys, image optimization). Scaffolded with `create-next-app@16` (Next.js 16), TypeScript, Tailwind CSS, App Router, `src/` dir, import alias `@/*`, ESLint, ID `web/`.
- **2026-09-19 — Icons: `lucide-react`.** Installed in `web/`.
- **2026-09-19 — Styling glue: `clsx` + `tailwind-merge`**, exposed as `cn()` in `web/src/lib/utils.ts`. Installed preemptively because reactbits.dev/21st.dev components almost universally import `cn` from a utils module — added now to avoid every first paste breaking on a missing import.
- **Analytics: still not decided.** GTM+GA4 vs. a lightweight privacy-first option (Plausible/Umami/Fathom) — revisit after the rebuild, not blocking section work.
- **2026-09-19 — shadcn CLI initialized in `web/`, `@react-bits` registry registered.** Ran `npx shadcn@latest init -y -d` (style `base-nova`, headless primitives via `@base-ui/react` — this shadcn version defaults to Base UI, not Radix). This swapped `web/src/lib/utils.ts`'s `cn()` from hand-rolled clsx+tailwind-merge to a re-export of the `cn` npm package (same API, verified no consumer impact) and added `web/src/components/ui/button.tsx` as a demo primitive. Also rewrote `web/src/app/globals.css` with the full shadcn Tailwind v4 theme-token setup (light/dark via a `.dark` class) — a solid foundation for the still-undecided dark/light mode task. Manually added `"@react-bits": "https://reactbits.dev/r/{name}.json"` to `web/components.json`'s `registries` field (not set by init) so `npx shadcn@latest add @react-bits/<Name>-TS-TW` works. Verified via `--dry-run` against `AeroShards-JS-CSS`: resolves fine, but **components pulled this way land flat in `web/src/components/`** (not nested under `ui/`), and reactbits ships multiple variant suffixes per component (`-JS-CSS`, `-TS-TW`, etc.) — always prefer `-TS-TW` to match this project's TypeScript+Tailwind stack; flag it to the user if a wanted component has no TS-TW variant.
- **2026-09-19 — `@21st` registry also registered, but needs an API key (unlike `@react-bits`).** The user asked about `npx @21st-dev/cli add <author>/<slug>` (a separate CLI package from shadcn's). Under the hood it just prints/proxies a `shadcn add` call against `https://21st.dev/r/<author>/<slug>?api_key=...` — so it uses the same shadcn registry protocol, just gated by auth. Added `@21st` to `web/components.json`'s `registries` with the `params`-based auth form (`"params": {"api_key": "${API_KEY_21ST}"}`), and created `web/.env.example` documenting the required `API_KEY_21ST` var (get one at https://21st.dev/mcp). Verified via `--dry-run` that the config is wired correctly — it fails with a clear "needs API_KEY_21ST" message, which is expected until the user adds their own key to `web/.env.local` (gitignored, not created yet — `.env*` is already covered by `web/.gitignore`). Once that's in place, install syntax is `npx shadcn@latest add @21st/<author>/<slug>` — same shape as `@react-bits`, no need for the separate `@21st-dev/cli` package.
- **2026-09-19 — `API_KEY_21ST` is set in `web/.env.local` and the registry works** (verified: `npx shadcn@latest add @21st/prebuiltui/cookies --dry-run` resolved correctly). Along the way the user briefly pasted the real key into `.env.example` instead of `.env.local` — caught before it was committed (checked git log, only the empty placeholder was ever committed), moved to `.env.local`, `.env.example` restored to blank. No rotation needed, it never left local disk.
- **2026-09-19 — User decided to paste 21st.dev components manually rather than use any CLI.** Root cause: `@21st-dev/cli add` (the separate `21st-dev/cli` package) doesn't read `.env.local` — only real shell env vars or `--token` — so it kept failing even with the key correctly set, which is what `npx shadcn@latest add @21st/...` directly *does* read. That direct form is confirmed working, but the user called the overall CLI experience "kinda broken" and would rather just paste code directly. **Going forward: treat 21st.dev components as pasted code, same as react-bits' pasted-code path — don't suggest the CLI route unless the user brings it up again.** The `@21st` registry config stays in place either way, it's just not the default path anymore.
- **2026-09-19 — Icons: switched from static `lucide-react` usage to the `lucide-animated` shadcn registry.** `lucide-react` was installed as a dependency but had zero actual usages in `web/src` (only hand-rolled inline SVGs and one custom GSAP hamburger icon existed). Registered `"@lucide-animated": "https://lucide-animated.com/r/{name}.json"` in `web/components.json` (public, no auth, same pattern as `@react-bits`). Verified via browser hover-test (screenshot pixel diff on lucide-animated.com's own demo grid, then again on localhost after installing) that these aren't just CSS color-transition icons — each is a `forwardRef` div-wrapped component built with Motion (`motion` npm package) whose SVG `<path>`/`<circle>` elements have `pathLength`/`pathOffset`/`rotate` variants that tween on `onMouseEnter`/`onMouseLeave` (plus an imperative `startAnimation`/`stopAnimation` handle for manual triggering). Install per-icon: `npx shadcn@latest add "@lucide-animated/<icon-name>"` — lands in `web/src/components/ui/`. Sizing is via the component's `size` prop (pixels), not a Tailwind `size-*` class, since that class would only resize the wrapper `<div>`, not the inner SVG. **Caveat flagged to the user, not yet resolved either way**: these are Lucide's generic outline style, not brand-accurate logos — the GitHub/LinkedIn icons now in Hero look close but aren't pixel-identical to the real brand marks.
